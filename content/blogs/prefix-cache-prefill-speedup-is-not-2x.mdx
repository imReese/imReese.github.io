很多人第一次理解 Prefix Cache 时，会产生一个自然直觉：

> 如果 50% prompt 已经命中缓存，那么 Prefill 应该接近 2× 加速。

这个直觉对于线性计算成立，但对于现代 LLM Attention 并不成立。

真正的问题不是：

> 命中了多少 token？

而是：

> 命中的 token 消除了哪些计算？剩余 token 还需要访问哪些状态？

## MHA: 为什么 50% hit 只减少 25% Attention FLOPs

长度为 N 的 causal attention，其计算区域是三角形：

$$
\frac{N(N+1)}{2}\approx\frac{N^2}{2}
$$

如果前半段 prefix 已经缓存：

```
[cached prefix][new tokens]
|-------------|------------|
```

新的 token 仍然需要 attend 整个历史 KV。

剩余计算：

$$
\sum_{i=1}^{N/2}(N/2+i)
\approx\frac{3N^2}{8}
$$

相对于原始：

$$
\frac{3N^2/8}{N^2/2}=0.75
$$

因此：

> 50% Prefix Cache 命中，只意味着 Attention 计算剩余约 75%，不是 50%。

更一般地：

$$
R_{attn}(\alpha)=1-\alpha^2
$$

其中 α 是 prefix hit ratio。

|Hit|Attention 剩余|Attention speedup|
|-|-:|-:|
|50%|75%|1.33×|
|75%|43.75%|2.29×|
|90%|19%|5.26×|

## 为什么不是 2×？

Prefix Cache 省掉的是：

```
prefix token 作为 Query 的计算
```

但没有省掉：

```
new token Query 对 prefix KV 的访问
```

所以后半段 token 仍然需要读取整个历史。

## Attention 结构决定收益

### MHA / GQA / MQA

虽然 KV 大小不同：

- MHA: 每个 head 独立 KV
- GQA: 多个 Q head 共享 KV head
- MQA: 所有 Q head 共享 KV

但是 attention pattern 都是：

```
new query -> all previous states
```

所以都接近：

$$
1-\alpha^2
$$

### MLA

MLA 最大变化是缓存对象：

```
MHA:
K + V

MLA:
latent KV + RoPE key
```

它极大减少 cache footprint，但 attention 仍然需要访问历史状态。

所以：

> MLA 解决的是 cache size，不改变 prefix reuse 的二次复杂度本质。

### SWA

Sliding Window Attention：

$$
O(NW)
$$

历史被限制在窗口 W 内。

因此 prefix reuse 更接近线性：

$$
R_{swa}(\alpha)\approx1-\alpha
$$

50% hit 更接近 2× attention-only 加速。

### KDA

KDA 不保存逐 token KV，而维护递归状态：

```
S0 -> S1 -> S2 -> ... -> SN
```

如果保存 checkpoint：

```
S(N/2)
       |
       continue
```

那么收益更接近：

$$
R_{kda}(\alpha)\approx1-\alpha
$$

但是 checkpoint interval 会影响 replay 成本。

### DSA

DSA 的问题更复杂，因为需要复用的不只是 KV：

```
KV
+
selection/index metadata
```

如果只缓存 KV：

- indexer 仍需重新计算
- sparse routing 仍可能产生开销

所以 DSA 说明了：

> KV hit 不一定等于 Attention State hit。

## 从 Attention 到整个 Transformer Block

真实 Prefill 不只有 Attention。

假设：

```
Attention FLOPs = 40%
MLP FLOPs      = 60%
```

50% prefix hit：

```
Attention remaining = 75%
MLP remaining       = 50%
```

整体：

$$
0.4\times0.75+0.6\times0.5=0.6
$$

理论加速：

$$
1/0.6=1.67\times
$$

所以工程上更合理的预期是：

> 50% prefix hit 通常带来约 1.5~1.7× prefill 提升，而不是 2×。

## 从 KV Cache 到 Attention State Cache

现代模型越来越说明一个事实：

缓存对象正在变化。

|模型|需要复用的状态|
|-|-|
|MHA/GQA|KV tensor|
|MLA|latent KV|
|SWA|window KV|
|DSA|KV + selection state|
|KDA|recurrent checkpoint|

未来 cache abstraction 更像：

```
Attention State Store
```

而不是简单：

```
KV Store
```

## 真实系统还会受到什么影响？

理论 FLOPs 只是第一层。

实际 serving 还受：

- KV/page lookup
- radix tree matching
- memory bandwidth
- GPU/CPU/NVLink/RDMA transfer
- batching 调度
- cache eviction

影响。

因此 Prefix Cache 的正确理解应该是：

> 它减少重复状态计算，但收益由 Attention 结构、缓存对象、系统实现共同决定。

这也是为什么下一代 LLM serving 基础设施的核心问题，不再只是：

```
如何保存 KV
```

而是：

```
如何描述、匹配、复用 Attention State
```
