Prefix Cache 命中一半 token，Prefill 就能快两倍——这个直觉只对**每个 token 成本相同**的线性计算成立。

Full Causal Attention 不是这样。越靠后的 Query，能看到的 Key 越多：第一个 Query 只看一个位置，最后一个 Query 要看完整前缀。命中前 50% token，跳过的是 Attention 矩阵左上角较小的三角形，而不是一半面积。

本文只回答一个问题：**从逻辑 Prefix 命中率出发，怎样逐层推导 Attention 剩余计算、完整 Prefill 的理想上界，以及最终需要实测的真实收益？**

## 先统一六个容易混用的术语

- **Prefix hit ratio**：索引逻辑匹配到的连续 prefix token 数与完整输入长度之比，本文记为 $\alpha$。它描述 match，不保证状态已经可用。
- **Reusable boundary**：所有续算必需状态都完整、版本一致并对齐到的最晚 token 边界。不同 state group 共同可用时，通常取最短的那个边界。
- **Effective reuse**：runtime 真正恢复成功并能够跳过计算的 token 范围。它不大于 logical prefix match，还会受到 page、checkpoint 与状态完整性的限制。
- **Load-back**：从本地或远端 cache 找到对象后，把它读回 runtime 可消费的位置并完成必要同步的过程。
- **Attention-only speedup**：基线 Attention FLOPs 与剩余 Attention FLOPs 的比值；不包含 MLP、投影、通信和 cache 恢复。
- **Full-prefill speedup**：完整 Prefill 基线成本与复用后端到端成本的比值；真实值应包含排队、load-back、replay 和 runtime 开销。

因此，**cache hit 不等于 runtime successfully restored**，logical prefix match 也不等于 effective reusable prefix。后文的 FLOPs 曲线是理想上界；除非明确写成实测，否则它们都不是 TTFT 或生产吞吐结论。

把完整 prompt 长度记为 $N$，Prefix Cache 命中的长度记为 $P=\alpha N$。只看 Attention 主体时：

$$
\text{remaining FLOPs}
=
1-\alpha^2,
$$

$$
\text{ideal speedup}
=
\frac{1}{1-\alpha^2}.
$$

当 $\alpha=0.5$，仍有 $75\%$ 的 Attention FLOPs 需要执行，理想加速只有：

$$
\frac{1}{1-0.5^2}
=
\frac{1}{0.75}
\approx
1.33\times.
$$

## Prefix Cache 跳过的是旧 Query，不是旧 Key

没有 Prefix Cache 时，长度为 $N$ 的 Prefill 会形成一个下三角 Attention 矩阵。忽略对角线和常数项，其面积是：

$$
F_{\text{full}}
\propto
\int_0^N x\,dx
=
\frac{N^2}{2}.
$$

命中长度为 $P$ 的 Prefix 后，前 $P$ 个 token 的各层输出与 KV/latent state 已经存在，旧 Query 行不必重算。但新增的 Query 仍然要读取旧 Prefix 的 Key/Value：

```text
cached prefix queries [0, P)
  不再执行

new suffix queries [P, N)
  仍需 attend to keys [0, current_position]
```

因此跳过的工作量是左上角边长为 $P$ 的旧三角形：

$$
F_{\text{skip}}
\propto
\frac{P^2}{2}.
$$

剩余工作量为：

$$
\begin{aligned}
F_{\text{remain}}
&=F_{\text{full}}-F_{\text{skip}}\\
&\propto\frac{N^2-P^2}{2}\\
&=\frac{N^2(1-\alpha^2)}{2}.
\end{aligned}
$$

除以完整 Prefill 的 $N^2/2$，就得到 $1-\alpha^2$。

这个推导揭示了一个容易忽略的事实：**Prefix 最前面的 token 最便宜，最后面的 token 最贵。** 命中 50% token 跳过的恰好是较便宜的 25% Attention 面积；剩下 50% Query 行包含了较长的历史依赖。

## 同一个命中率，在 MHA、MLA、SWA、KDA 上不是同一条曲线

Prefix Cache 的收益取决于 Attention 如何消费历史。下面的交互曲线统一把完整请求的 Attention 工作量归一化为 1，并比较三种理想模型：

- **MHA / MLA**：完整 Causal Attention，剩余比例是 $1-\alpha^2$；
- **SWA**：只看最近窗口 $W$，本文可视化固定为 $W=0.25N$；
- **KDA recurrence only**：递归扫描与 token 数近似线性，但只能从不晚于命中位置的完整 checkpoint 继续。

### MHA、GQA、MQA 与 MLA：Cache 表示变了，因果三角形没有消失

MHA、GQA 与 MQA 都保存逐 token 的 K/V，但共享粒度不同：MHA 为每个 Query Head 保存独立 K/V，GQA 让一组 Query Heads 共享 KV Head，MQA 则让所有 Query Heads 共享一组 K/V。这些变化会缩小 Cache 宽度，却不会改变 `new query → all previous states` 的 Full Causal 依赖。

MLA 进一步把历史压成 KV latent 与解耦 RoPE key，显著改变每 token 的 Cache 宽度和读写方式。但只要主 Attention 仍对完整历史做 Causal Attention，它的 Query-Key 依赖仍是下三角：

$$
R_{\text{MHA/MLA}}(\alpha)
=
1-\alpha^2.
$$

MLA 可以让 cache 更小、内存流量更低，也可能改变 kernel 的常数；这些收益不能把 Prefix 命中率公式直接改成 $1-\alpha$。

### SWA：上下文超过窗口后，边际成本趋向线性

Sliding Window Attention 的第 $t$ 个 Query 最多读取 $W$ 个 Key。累计工作量可近似写成：

$$
A_W(x)
=
\begin{cases}
\frac{x^2}{2}, & x\le W,\\
Wx-\frac{W^2}{2}, & x>W.
\end{cases}
$$

命中比例为 $\alpha$ 时，剩余比例是：

$$
R_{\text{SWA}}(\alpha)
=
\frac{A_W(N)-A_W(\alpha N)}{A_W(N)}.
$$

当 Prefix 和完整请求都远大于窗口，后续每个 token 的 Attention 成本接近固定的 $W$，于是曲线逐渐接近线性模型。这里仍不能只看逻辑命中率：SWA 的 trailing state、local window page 与其他 Attention 层必须落在同一个可恢复边界。

### KDA：递归计算可以线性跳过，恢复边界却必须对齐

KDA 一类线性 Attention 不再为每个 Query 回读完整历史，而是递推有限状态。若完整 Prefill 的 recurrence 扫描成本近似为 $O(N)$，逻辑匹配长度为 $P_{\text{match}}=\alpha N$，checkpoint 间隔为 $C$，能够直接恢复的位置要先向下对齐：

$$
P_{\text{eff}}
=
\left\lfloor\frac{P_{\text{match}}}{C}\right\rfloor C,
$$

$$
R_{\text{KDA-recurrence}}
=
\frac{N-P_{\text{eff}}}{N}.
$$

交互图默认取 $N=32768$、$C=4096$。例如 logical hit 为 90% 时，匹配位置约为 29491，但最近 checkpoint 在 28672；recurrence 至少还要处理 4096 token，所以理想上界是 8×，不是把 $1/(1-0.9)$ 直接算出的 10×。调整 checkpoint interval 可以看到这条阶梯曲线如何变化。

这里的“存在 checkpoint”仍是强条件。一个可续算的 checkpoint 必须包含该边界完整的 recurrent state；如果 ShortConv 或其他续算状态存在，也必须一起完整、版本一致且对齐。只有 token hash 命中、只有 MLA page 命中，或只有 recurrent matrix 存在，都不能证明请求能从该边界直接恢复。

曲线只计算 recurrence remaining tokens，并假设对齐 checkpoint 可立即使用。它忽略 checkpoint lookup、load、跨层或跨设备传输、同步，以及恢复状态本身的成本；未对齐的 prefix token 被计入 remaining tokens，但没有额外建模 checkpoint replay 的实现开销。因此它是 **exact aligned checkpoint 条件下的 ideal upper bound**，不是生产环境收益预测。

## Real-world Attention Patterns

上面的公式描述 dependency pattern，而不是某个模型版本。下面的家族名称只是帮助把抽象模式映射到常见实现；具体模型仍应以自己的配置和代码为准。

| Pattern | Representative examples     | Cache implication              |
| ------- | --------------------------- | ------------------------------ |
| GQA     | Llama / Qwen / GLM families | KV cache；causal geometry 不变 |
| MLA     | DeepSeek family             | latent KV state                |
| SWA     | Mistral family              | windowed history reuse         |
| KDA     | Kimi family                 | recurrent checkpoint state     |

这张表不改变推导：先识别历史依赖是 full causal、windowed 还是 recurrent，再选择对应的 remaining-computation 模型。

## 为什么 logical hit 还要经过 reusable boundary

Prefix Cache 能跳过计算的前提，不只是索引找到了相同 token。Runtime 必须恢复该 Attention pattern 续算所需的完整状态：它可能是 KV pages、MLA latent、window trailing state，或 recurrent checkpoint。下面的演进图用于比较这些恢复边界，而不是给模型做分类。

这里的系统结论只有一个：object/page `match` 只说明某个键存在；effective reuse 要求所有必需状态在同一 token 边界完整命中，并成功 load-back 到执行引擎。对 hybrid model，最终可跳过的长度通常是各状态组共同连续前缀的最小值。

## Attention 加速不是完整 Prefill 加速

前面的 $1/(1-\alpha^2)$ 只描述 Full Causal Attention 主体。Prefill 还包含 embedding、normalization、QKV projection、output projection、MLP/MoE、collective communication 与 runtime 调度。

假设基线 Transformer block FLOPs 中 Attention 占比为 $\beta$，其余按 token 近似线性的算子占比为 $1-\beta$。忽略 cache 开销时：

$$
R_{\text{attention}}=1-\alpha^2,
\qquad
R_{\text{token-wise}}=1-\alpha,
$$

$$
R_{\text{block}}
=
\beta(1-\alpha^2)
+
(1-\beta)(1-\alpha),
$$

$$
S_{\text{block, ideal}}
=
\frac{1}{R_{\text{block}}}.
$$

下面的交互把 Attention-only、token-wise 与完整 block 的理想 FLOPs 加速放在一起。默认 $\alpha=50\%$、$\beta=50\%$；此时 block 剩余 62.5%，理想加速为 1.60×。同样在 50% hit 下，$\beta=30\%,50\%,70\%$ 分别约为 1.74×、1.60×、1.48×：Attention 占比越高，前半段较便宜的因果三角形对整体加速的限制越明显。

<PrefillSpeedupExplorer />

这个 full-block FLOPs 模型可以作为 full-prefill compute 的第一层近似，但它仍不是端到端延迟模型。再把 lookup、Host/Storage load、反序列化、H2D、同步、checkpoint replay 与调度等待归一化为 $h$，才可以粗略写成：

$$
S_{\text{e2e}}
\approx
\frac{1}
{\beta(1-\alpha^2)+(1-\beta)(1-\alpha)+h}.
$$

例如 $\alpha=0.5$、$\beta=0.6$ 且暂时令 $h=0$，剩余模型计算约为：

$$
0.6\times0.75
+
0.4\times0.5
=
0.65,
$$

对应约 $1.54\times$，仍不是 $2\times$。远端 Cache 的 $h$ 若大于省下来的计算，命中甚至可能比本地 recompute 更慢。

这个模型只是建立量纲，不应替代 profiling。FlashAttention 的 tile、chunked prefill、batch packing、Tensor Parallel 通信和 MoE 路由都会让真实曲线偏离连续面积模型。Attention FLOPs speedup 不等于 TTFT speedup，ideal upper bound 也不等于生产吞吐。

## 把命中率变成可解释的性能指标

只上报一个 `prefix_hit_rate`，很难解释 TTFT。至少应把下面几层分开：

| 指标                             | 回答的问题                                             |
| -------------------------------- | ------------------------------------------------------ |
| logical matched tokens           | Radix/hash 最长匹配到了多少 token？                    |
| restorable matched tokens        | 所有必需 Attention state 共同完整到了哪个边界？        |
| replay tokens                    | 因 page/checkpoint 粒度不对齐，需要补算多少 token？    |
| state lookup / load-back latency | 命中状态从 metadata 到 device 可用花了多久？           |
| suffix prefill latency           | 恢复后真正计算新 token 花了多久？                      |
| TTFT                             | 排队、调度、传输、Prefill 与首 token Decode 合计多久？ |

对 Full Causal MHA/MLA，还可以同时上报一个由命中率推导出的 Attention 工作量指标：

$$
\text{attention work avoided}
=
\alpha^2,
$$

而不是用 $\alpha$ 代替。这样 50% token hit 会明确显示为 25% Attention work avoided，监控、容量规划和性能回归分析就不会混用两个不同的量。
