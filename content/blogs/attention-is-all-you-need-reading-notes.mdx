我以前读 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)，会把注意力放在公式上：

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V
```

现在再读，我更关心它删掉了什么。

Transformer 最狠的一刀不是“用了 attention”，而是把序列建模里那条按时间步传递的 recurrence 拿掉了。RNN 的状态像一根链条，`h_t` 要等 `h_{t-1}`。Transformer 改成：同一层里，每个 token 可以直接和其它 token 建立关系。

这一步把问题从时间依赖链改成了矩阵计算，也把后来的系统问题埋下了。

## 从一条链变成一张表

RNN 的直觉很自然：一句话从左到右读，当前状态携带过去信息。

```text
x1 -> h1 -> h2 -> h3 -> h4
```

这条链的问题是，训练时序列内部不好并行，长距离依赖也要经过很多中间状态。

Self-attention 换了一个问法：如果第 4 个 token 想知道第 1 个 token 是否重要，为什么一定要靠 `h2`、`h3` 一步步传？为什么不能直接算它们之间的关系？

```text
token i
  -> scores all token j
  -> collects weighted values
```

这就是 attention 公式背后的工程形状。它把“序列中信息怎样流动”改成了“一个 token 如何在同一层里寻址其它 token”。

## QKV 像一次寻址过程

QKV 不只是三组投影。更贴近系统直觉的理解是：

```text
Query: 当前 token 发出的查询
Key:   每个历史 token 暴露的地址/标签
Value: 命中以后读回来的内容
```

`QK^T` 像是在算 query 和所有 key 的匹配程度，softmax 得到读取权重，最后用这组权重去聚合 value。

这样看，Q 和 K 定义“怎么找”，V 定义“找到了拿什么回来”。这比“每个词看每个词”更准确，因为匹配空间和内容空间被拆开了。

Multi-head attention 继续把这件事复制多份：不同 head 有不同的投影空间，可以学到不同的寻址方式。后来的 MQA/GQA 之所以有工程意义，也正是因为 K/V head 的数量会直接影响 KV Cache 大小。

```text
more KV heads
  -> more K/V tensors per token
  -> larger KV cache
  -> more memory pressure during serving
```

这就是模型结构和 serving 系统开始接上的地方。

## mask 和 position 是两个契约

Self-attention 给 token 之间开了直接通道，但这条通道必须被约束。

第一个约束是 mask。

机器翻译里的 decoder masked self-attention，和今天 decoder-only LLM 的 causal attention，本质上都在守同一个契约：生成当前位置时不能看未来。

```text
token t can attend to:
  token <= t

token t cannot attend to:
  token > t
```

这个契约会一路传到 KV Cache。缓存里的 K/V 代表“已经出现过的 token”。prefix reuse、cache hit、remote KV load back 都不能破坏这个顺序。

第二个约束是 position。

去掉 recurrence 后，attention 本身不知道 token 先后。原论文用 sinusoidal positional encoding，今天常见 RoPE、ALiBi 等变体，但它们都在补同一件事：让模型知道 token 在序列里的相对或绝对位置。

长上下文系统里，position 不是小细节。复用一段 KV，不只是问 token 内容是否相同，还要问这段 K/V 在当前上下文位置下是否仍然有效。

## 训练阶段省掉的链，推理阶段变成了缓存

训练时，整段序列可以一起进模型，所有 token 的 Q/K/V 在每层批量算出来。

推理时不一样。自回归生成每吐一个新 token，都要看前面的历史。如果每一步都重算完整 prompt 和已生成内容，成本会不可接受。

所以系统保存历史 token 的 K/V：

```text
prefill:
  prompt tokens
  -> compute K/V for every layer
  -> store KV cache

decode:
  new token
  -> compute current Q/K/V
  -> Q attends to cached historical K/V
  -> append new K/V
```

KV Cache 不是一个附加优化，而是 decoder-only LLM serving 的基本状态。

它的大小随 layer、sequence length、KV heads、head dimension 和 dtype 增长：

```text
KV cache size
  ~= layers
   * sequence length
   * KV heads
   * head dimension
   * 2
   * dtype bytes
```

于是 attention 从论文里的计算结构，变成了 serving runtime 里最重要的内存压力之一。

## FlashAttention 和 PagedAttention 不是同一种答案

沿着 attention 往后看，经常会遇到两个名字：FlashAttention 和 PagedAttention。它们都围绕 attention，但解决的问题不一样。

FlashAttention 更靠近计算过程。它关心 attention kernel 怎么减少 HBM 读写，怎么避免把完整 attention matrix 物化出来，怎么让 prefill / training 更高效。

PagedAttention 更靠近推理状态管理。它关心 KV Cache 怎么按 block 管理，怎么避免连续显存预留，怎么支持共享前缀和 copy-on-write。

```text
FlashAttention:
  optimize attention computation
  reduce memory traffic during score/value aggregation

PagedAttention:
  optimize KV cache placement
  reduce fragmentation and over-reservation during serving
```

如果把两者都叫 attention 优化，很容易错过它们的层级差异。

## 门打开以后

`Attention Is All You Need` 不只是把 RNN 换成 attention。它把序列关系变成了可并行计算的矩阵，也让自回归推理不得不长期保存 K/V 状态。

这就是为什么这篇论文会一路连到 KV Cache、PagedAttention、FlashAttention、prefix cache、HiCache 和 remote KV store。attention 成为主干以后，K/V 就不再只是中间张量，而是系统资源。
